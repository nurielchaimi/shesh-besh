# טורניר שש-בש

אתר לטורניר שש-בש של ערב אחד: המשתתפים נרשמים בעצמם מהטלפון, ובכל משחק האתר אומר להם מול מי הם משחקים (עם קצת רקע על היריב) ובאיזה שולחן. כשהמשחק נגמר הם מדווחים על התוצאה והאתר שולח אותם למשחק הבא. מסך הקרנה מתעדכן לבד.

האתר סטטי (בלי שרת), ולכן אפשר לארח אותו ב-GitHub Pages. הנתונים החיים נשמרים ב-Firebase (חינמי).

## איך הערב עובד

1. **חוקים והרשמה.** מי שנכנס לקישור בפעם הראשונה רואה קודם את עמוד החוקים (נוסח החוקים נמצא בקובץ אחד, `js/rules.js`, וקל לערוך אותו), ואחר כך את טופס ההרשמה. המארגן פותח את `admin.html` ומשתף את הקישור של `index.html` (על מסך ההקרנה יש גם QR). כל נרשם ממלא שם, מה הוא לומד, רמת ניסיון ומשפט אחד על עצמו. הפרטים האלה מוצגים ליריבים כ"רקע".
2. **הגרלה.** מספר המשתתפים לא קבוע: האתר בוחר לבד גודל בית שנותן עץ הדחה מסודר (למשל 64 שחקנים בבתים של 4, ו-80 בבתים של 5), ומסדר פטורים כשצריך. ההגרלה סוגרת את ההרשמה.
3. **משחק.** כל שחקן רואה: מספר שולחן, מי היריב, הרקע שלו, ומה לעשות. בסוף המשחק הוא לוחץ "ניצחתי", "הפסדתי" או את גרסת המארס.
4. **אישור.** התוצאה נקבעת כששני השחקנים מדווחים אותו דבר. אם רק אחד דיווח, השני רואה "נועה דיווחה שניצחה אותך במארס, נכון?" ולוחץ אישור. אם יש אי-הסכמה או שחקן לא מגיב, המארגן מכריע בלחיצה.
5. **המשחק הבא.** כל בית מתקדם לסיבוב הבא ברגע שהמשחקים שלו נגמרו, בלי לחכות לשאר. בעץ ההדחה כל משחק נוצר ברגע ששני המשחקים שמזינים אותו נגמרו, על שולחן פנוי. השחקן מקבל רטט בטלפון ומסך חדש.

## הכללים

- **שלב הבתים:** כולם משחקים נגד כולם בבית, לכל בית שולחנות קבועים.
- **ניקוד:** ניצחון = נקודה, מארס = 2 נקודות, ניצחון טכני = נקודה. שוויון נשבר לפי: ניצחון ישיר, מספר ניצחונות, מספר מארסים, ואז הכרעה ידנית של המארגן.
- **שלב ההדחה:** מהבית עולים 2 הראשונים (אפשר לשנות). העץ מסודר לפי תוצאות הבתים, ושחקנים מאותו בית לא נפגשים בסיבוב הראשון.

## חשוב: הטייס האוטומטי

מי שמזיז את הטורניר קדימה הוא `admin.html` כשהוא פתוח אצל מארגן (כפתור "טייס אוטומטי", דלוק כברירת מחדל). הוא הופך דיווחים תואמים לתוצאה, מעביר בתים לסיבוב הבא ובונה את עץ ההדחה. **צריך לפחות מארגן אחד שהדף הזה פתוח אצלו לאורך כל הערב** (מחשב או טלפון שלא נרדם). אם הוא נסגר, התוצאות עדיין נשלחות, אבל שום דבר לא מתקדם עד שהוא נפתח שוב.

## ניסוי מקומי (בלי Firebase)

```bash
node dev-server.mjs
```

פותחים `http://localhost:5173/admin.html`. כל עוד `config.js` ריק האתר במצב הדגמה: הנתונים נשמרים רק בדפדפן הזה, וטאבים באותו דפדפן מתעדכנים זה מזה. בלשונית "הרשמה והגדרות" יש כפתורים להוסיף 20, 64 או 80 נרשמי דמו. כדי לשחק בתור שחקן ולבדוק את חוויית השחקן, פותחים `index.html?as=<מזהה שחקן>` (המזהה מופיע ב-localStorage תחת `sheshbesh:signups`). את הטייס האוטומטי מפעיל טאב ניהול פתוח.

בדיקות אוטומטיות של מנוע הטורניר (טורנירים שלמים עם 4 עד 200 משתתפים, מחלוקות, פרישה):

```bash
node --test tests/engine.test.mjs
```

## חיבור Firebase (פעם אחת, כ-15 דקות)

1. נכנסים ל-[console.firebase.google.com](https://console.firebase.google.com) ויוצרים פרויקט (אפשר בלי Analytics).
2. **Build → Firestore Database → Create database**. בוחרים מיקום קרוב (למשל `eur3`) ומצב Production.
3. **Build → Authentication → Get started**. מפעילים שני ספקים: **Email/Password** ו-**Anonymous**. (שחקנים נכנסים אנונימית, וזה מה שמקשר כל שחקן לטלפון שלו ומונע ממישהו לדווח בשם אחר.) בלשונית Users יוצרים משתמש מנהל עם אימייל וסיסמה חזקה.
4. ב-Firestore, לשונית **Rules**: מדביקים את התוכן של `firestore.rules`, מחליפים את `ORGANISER@example.com` באימייל של המנהל ולוחצים Publish.
5. **Project settings → Your apps → Web (`</>`)**: רושמים אפליקציה ומעתיקים את ערכי `firebaseConfig` אל `config.js`, בין הסוגריים של `firebase`.

מפתח ה-API ב-`config.js` נועד להיות גלוי. ההגנה היא כללי האבטחה בשלב 4: כולם רואים, רק המנהל משנה את הטורניר, ושחקן יכול לדווח רק על משחק שהוא משתתף בו ורק בשם עצמו.

## העלאה ל-GitHub Pages

1. יוצרים repository חדש ב-GitHub ומעלים אליו את כל תוכן התיקייה.
2. **Settings → Pages → Build and deployment**: Source = `Deploy from a branch`, Branch = `main`, תיקייה `/ (root)`.
3. אחרי כדקה האתר זמין ב-`https://<שם-משתמש>.github.io/<שם-הריפו>/`:
   - שחקנים והרשמה: `index.html` (זה הקישור לשתף בקבוצה)
   - מסך הקרנה: `tv.html`
   - ניהול: `admin.html`
4. אם ההתחברות של המנהל נכשלת, בודקים ב-Firebase תחת Authentication → Settings → Authorized domains שהדומיין `<שם-משתמש>.github.io` מופיע.

## ביום האירוע

- מחברים את מסך ההקרנה ופותחים `tv.html` במסך מלא (F11). לפני ההגרלה הוא מציג QR גדול ומספר נרשמים. אחר כך הוא מתחלף בין שולחנות, בתים, עץ ותוצאות אחרונות. אפשר לנעול סצנה עם `tv.html?scene=tables` (או `groups`, `bracket`, `recent`), ולקבוע מהירות עם `?interval=15`.
- מארגן אחד לפחות נכנס ל-`admin.html` ומשאיר אותו פתוח. מארגן נוסף יכול לפתוח אותו במקביל, והטייס האוטומטי בטוח להרצה בשניהם.
- בלשונית "חי" מופיעים בראש הדף משחקים שדורשים החלטה (אי-הסכמה) ומשחקים שממתינים לאישור. הכפתורים "ניצח", "מארס" ו-"טכני" בכל כרטיס קובעים תוצאה ישירות.
- שחקן שלא הגיע או פרש: "טכני" בשולחן, או "פרש" בלשונית שחקנים.
- שחקן שהחליף טלפון או ניקה דפדפן: בלשונית שחקנים לוחצים "שחרר", והוא תופס את השם שוב בלי הרשמה חדשה.
- אפשר להוסיף נרשמים ידנית (שם בכל שורה). הם תופסים את השם שלהם מהטלפון דרך "המארגנים כבר רשמו אותי".
- **כלים → הורד גיבוי** מדי פעם. אפשר לשחזר מהקובץ.
- מומלץ חזרה גנרלית עם חמישה אנשים ושלושה טלפונים לפני האירוע, כולל הרשמה, דיווח ואישור.

## מגבלות חינמיות של Firebase

התוכנית החינמית כוללת 50,000 קריאות ביום. עם 80 משתתפים ערב אחד ההערכה היא כ-25,000, אבל שווה לבדוק בחזרה גנרלית. מעבר ל-50 אלף האתר מפסיק להתעדכן עד סוף היום, ולכן כדאי לא לרענן את מסך ההקרנה בלי צורך.

## מבנה הקבצים

| קובץ | תפקיד |
|---|---|
| `js/engine.js` | כל לוגיקת הטורניר: הגרלה, לוח משחקים, דירוג, עץ, דיווחים והטייס האוטומטי |
| `js/store.js` | שכבת הנתונים: מצב הדגמה או Firebase (הרשמות, דיווחים, זיהוי שחקן) |
| `js/render.js` | רכיבי תצוגה משותפים |
| `index.html`, `tv.html`, `admin.html` | שחקנים והרשמה, הקרנה, ניהול |
| `firestore.rules` | כללי האבטחה |
